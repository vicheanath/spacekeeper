# Writing a scanner

A scanner discovers cleanup opportunities of one kind. This is SpaceKeeper's
only extension point, and it is the same one the built-in scanners use — there
is nothing privileged about shipping in the repository.

## Decide which kind you need

**Is it "look in this well-known folder"?** Write a `PathRule`. No code.

**Does it need real logic** — hashing, cross-referencing, querying a daemon,
dating something by a heuristic? Implement `Scanner`.

## Declarative: add a `PathRule`

Add one entry to [`catalog.rs`](../crates/spacekeeper-scanners/src/catalog.rs):

```rust
PathRule {
    id: "unity_library",
    name: "Unity Library folders",
    description: "Imported asset caches inside Unity projects",
    explanation: "Unity's imported copies of your project's assets. Unity \
                  rebuilds this folder the next time you open the project, \
                  which takes a few minutes once.",
    family: Family::Developer,
    category: Category::BuildArtifact,
    risk: RiskLevel::Safe,
    confidence: 0.9,
    paths: &["~/Unity/*/Library"],
    platforms: &["macos", "linux", "windows"],
    requires_tool: Some("unity"),
},
```

That is the entire change. `RuleScanner` handles existence checks, parallel
measurement, cancellation, size filtering, timestamps and guard enforcement.

### Path patterns

- a leading `~` is the user's home directory;
- a `*` component matches any single directory name (`~/Library/Caches/Firefox/Profiles/*`).

`..` is not supported, on purpose: it would be a way around the path guard's
prefix checks.

### Writing the `explanation`

This is the sentence a non-technical person reads before deciding, and it is the
part of a scanner most likely to be done badly. Two rules:

1. **Say what it is without jargon.** Not "DerivedData"; "build artifacts
   generated by Xcode".
2. **Say what happens after deletion.** "Safe to remove" is half an answer.
   "Xcode recreates them the next time you build, which takes longer that one
   time" is the whole answer.

A test asserts every explanation is longer than 40 characters. That catches
labels masquerading as explanations, but it cannot catch a bad one — review it
like prose, because it is.

### Choosing a risk level

| Level | Use when |
|---|---|
| `Safe` | the owning application regenerates it by itself, and the user will not notice |
| `Review` | not regenerated, costs a re-download, or might actually be wanted |
| `Dangerous` | never deletable; shown for information only |

A test enforces that AI models and device images are never `Safe` — they cost a
multi-gigabyte download or lose state, so they never get one-click deletion.

When unsure, choose `Review`. The cost of a wrong `Review` is a user clicking one
extra checkbox. The cost of a wrong `Safe` is deleted data.

### What a scanner cannot reach

Anything the guard classifies as `Caution` — `~/Documents`, `~/Pictures`,
`~/Desktop`, cloud drives, `.git` — is invisible to automated cleanup no matter
what a rule claims. There is deliberately no `~/Desktop` scanner for exactly
this reason: desktop files are things the user *made*, not things that arrived,
so the [size explorer](explorer.md) covers that folder instead, with the user
looking straight at it.

If a rule you add reports nothing on a machine where the folder clearly exists,
check whether it sits under a protected tree before debugging the pattern.

## Bespoke: implement `Scanner`

```rust
use spacekeeper_core::{
    Category, Family, Result, RiskLevel, ScanContext, ScanResult, Scanner,
    ScannerMetadata, EntryKind,
};

pub struct SteamScanner;

#[async_trait::async_trait]
impl Scanner for SteamScanner {
    fn metadata(&self) -> ScannerMetadata {
        ScannerMetadata {
            id: "steam_downloads".into(),
            name: "Steam download cache".into(),
            description: "Partially downloaded and unpacked game files".into(),
            explanation: "Temporary files Steam keeps while installing games. \
                          Steam re-downloads what it needs; installed games are \
                          not affected.".into(),
            family: Family::General,
            default_risk: RiskLevel::Safe,
            platforms: vec!["macos".into(), "linux".into(), "windows".into()],
            enabled_by_default: true,
            requires_tool: Some("steam".into()),
        }
    }

    async fn scan(&self, context: &ScanContext) -> Result<Vec<ScanResult>> {
        let progress = context.progress_for("steam_downloads");
        let control = context.control.clone();
        let path = context.resolve("~/Library/Application Support/Steam/steamapps/downloading");

        // Blocking filesystem work belongs on the blocking pool.
        let stats = tokio::task::spawn_blocking(move || {
            spacekeeper_core::fsutil::measure(&path, &control)
        })
        .await
        .map_err(|e| spacekeeper_core::Error::Other(anyhow::anyhow!(e)))??;

        progress.scanning(stats.files, stats.size, None);

        Ok(vec![ScanResult::builder("steam_downloads", path)
            .description(self.metadata().explanation)
            .size(stats.size)
            .kind(EntryKind::Directory)
            .category(Category::Cache)
            .risk(RiskLevel::Safe)
            .deletable(true)
            .last_accessed(stats.last_accessed)
            .confidence(0.9)
            .build()])
    }
}
```

Then register it:

```rust
registry.register(Arc::new(SteamScanner));
```

### Contract

- **Be independent.** No scanner may depend on another having run. Ordering is
  an implementation detail of the engine.
- **Check `context.control`.** Use `fsutil` and `walk` helpers and you get this
  for free; if you loop yourself, call `control.check()?` periodically.
- **Never walk the disk by hand.** `walk::walk` already skips protected
  directories, `.git`, and symlinks. A hand-rolled walk is a scanner that can
  forget one of those.
- **Use `spawn_blocking`** for filesystem work.
- **Return `Error::unavailable`** when the machine has nothing for you to do —
  it is recorded as *skipped*, not failed, and shows no error to the user.
- **Do not enforce safety yourself.** Propose a risk level and let policy decide.
  Nothing you set can widen what SpaceKeeper will delete, so there is no point
  trying.

### Progress

```rust
let progress = context.progress_for("my_scanner");
progress.scanning(files_seen, bytes_found, Some(path.display().to_string()));
```

Events are best-effort. Never let a progress failure affect a scan.

## Testing a scanner

Build a synthetic home with `tempfile` and assert on behaviour, not
implementation. Every built-in scanner has tests covering: it finds the thing;
it ignores what it should; it respects the size threshold; it refuses protected
paths; it handles a missing directory without erroring.

```rust
#[tokio::test]
async fn finds_the_download_cache() {
    let home = tempfile::tempdir().unwrap();
    write(&home.path().join("Library/Application Support/Steam/steamapps/downloading/x"), 5000);

    let context = ScanContext::new(home.path().to_path_buf());
    let results = SteamScanner.scan(&context).await.unwrap();

    assert_eq!(results.len(), 1);
    assert_eq!(results[0].size, Bytes(5000));
}
```

Add a case to [`end_to_end.rs`](../crates/spacekeeper-scanners/tests/end_to_end.rs)
if your scanner interacts with ranking or cleanup in an interesting way.

## Plugin roadmap

Today a "plugin" is a Rust type registered at startup, which means recompiling.
That is enough to keep the core open for extension, and it is how every built-in
scanner works — but it is not yet a plugin *system*.

The planned host runs third-party scanners out of process over the same
`Scanner` shape, with a WASM sandbox and no filesystem write capability at all.
The safety story does not change when that lands: a plugin still only proposes,
and `PathGuard` still decides. See the [roadmap](roadmap.md).
