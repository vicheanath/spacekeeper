# Contributing

## Setup

```bash
git clone https://github.com/spacekeeper/spacekeeper
cd spacekeeper/apps/desktop
npm install
npm run tauri dev
```

Needs Rust stable, Node 20+, and the
[Tauri v2 prerequisites](https://tauri.app/start/prerequisites/) for your OS.

## Before opening a PR

```bash
cargo test --workspace
cargo clippy --all-targets -- -D warnings
cargo fmt --all --check
cd apps/desktop && npm run typecheck && npm run build
```

CI runs exactly these.

## The one rule

**Never widen what SpaceKeeper is willing to delete without a test that says
so.**

If a change touches `protect.rs`, `cleanup.rs` or `apply_policy`, it needs a
test named after the guarantee it preserves — `symlinks_are_refused`, not
`test_cleanup_3`. Reviewers will ask for it.

Anything else is ordinary review.

## Adding a scanner

Most contributions are scanners, and most scanners are one row of data. See
[docs/scanners.md](docs/scanners.md). The short version:

- "look in a well-known folder" → add a `PathRule` to `catalog.rs`, no code;
- anything else → `impl Scanner`.

Write the `explanation` for someone who has never heard of the tool, and say
what happens *after* deletion — that field is the product.

## Style

**Rust** — `cargo fmt` defaults. Comments explain *why*, not *what*; if a
comment restates the code, delete it. `unsafe` is forbidden workspace-wide.
Prefer `.expect("what failed")` over `.unwrap()` where a message helps.

**TypeScript** — strict mode, no `any`. UI components live in
`src/components/`; primitives generated by the shadcn CLI live in
`src/components/ui/` and should generally be regenerated rather than hand-edited.

**Both** — match the surrounding code. A PR that reformats a file it did not
otherwise change will be asked to drop the noise.

## Commits

Present tense, describing the change: "Refuse symlinks in the cleanup engine",
not "fixed stuff". Reference an issue when there is one.

## Releasing

1. Bump the version in `Cargo.toml` (`[workspace.package]`),
   `apps/desktop/src-tauri/tauri.conf.json` and `apps/desktop/package.json`.
   They must all match.
2. Commit, then tag and push: `git tag v0.2.0 && git push origin v0.2.0`.

The Release workflow builds macOS (Apple Silicon and Intel), Linux (x64 and
ARM64) and Windows (x64 and ARM64), attaches the installers to a GitHub release
and publishes it once every build succeeds. A tag with a suffix such as
`v0.2.0-beta.1` is published as a pre-release. To check that everything builds
without releasing, run the workflow by hand from the Actions tab.

## Reporting bugs

For anything involving deleted data, include the scanner id, the path, and what
you expected. If SpaceKeeper deleted something it should not have, that is a
security issue — open an advisory rather than a public issue.
